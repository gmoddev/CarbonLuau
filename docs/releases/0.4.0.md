# CarbonLuau 0.4.0

Qualified experimental addon release candidate.

This release keeps the existing gameplay facade and adds bounded, provider-owned
addon packages inside CarbonLuau's shared Luau VM. The scripting API identity is
`CarbonLuau 0.4.0-experimental`; it is not stable or 1.0.

## Addon composition

Addon manifests can declare required and optional dependencies, a `main` module,
and explicit `publicModules`. Consumers import through their exact dependency
bindings:

```lua
local Economy = require("@economy")
local Formatting = require("@economy/formatting")

if addon:IsDependencyAvailable("metrics") then
    local Metrics = require("@metrics")
end
```

Local `require("private/util")` behavior is unchanged. Public modules return the
defining addon's canonical same-VM value, so shared tables and closures are shared
by reference. Private modules remain private. Missing, undeclared, stale or
non-public imports raise controlled ordinary Luau errors.

## Lifecycle and containment

- Providers register copied immutable schema-1 snapshots through
  `CarbonLuau.Addons` protocol 1.2.
- Required dependency loss retires and blocks affected consumers; restoration
  reconstructs eligible consumers against the new exact lifetime.
- Optional consumers do not hot-bind or hot-rebind.
- Provider unload retires its registrations. CarbonLuau reload invalidates all
  provider tokens and requires explicit fresh registration.
- One saturated addon cannot monopolize the global scheduler, and future-only
  tasks do not create persistent per-frame work.
- The 64 MiB VM default remains one shared cap, not a per-addon or process limit.

## Qualification

Root-only, 1, 10, 50 and 100-addon configurations passed on Windows and Linux.
The matrix covered memory and latency measurements, scheduler saturation,
shared-heap exhaustion, parser boundaries, provider and CarbonLuau unload/reload,
stale tokens, required/optional dependency transitions, native DLL teardown,
ASan, UBSan and leak detection. See the complete
[Foundation E record](../FoundationE.md).

The candidate source was subsequently reorganized into explicit managed and
native invariant owners without an intentional behavior or identity change. See
the [Foundation F architecture record](../FoundationF.md).

All source compilation is subsequently contained by the shipped pinned compiler
worker with a one-second wall deadline, bounded protocol and clean restart after
timeout or failure. Linux, sanitizer and packaging qualification passed. Windows
live/local Foundation G qualification remains deferred and unqualified, so the
Foundation G verdict is PARTIAL and this is not a fully Windows-qualified
compiler-worker claim. See the [Foundation G record](../FoundationG.md).

## Not included

There is no addon directory scanner, package downloader, remote registry,
lockfile, version solver or parallel package instance. Provider-defined C#
capabilities, root-to-addon imports, addons depending on the root, restricted
exposure profiles, async capabilities and per-addon hard heap isolation remain
deferred. Inventory/items and authenticated real-client qualification remain
outside the supported envelope described by the existing records.
