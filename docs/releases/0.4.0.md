# CarbonLuau 0.4.0

Qualified experimental addon and GUI release candidate.

This release keeps the existing gameplay facade and adds bounded, provider-owned
addon packages inside CarbonLuau's shared Luau VM. The scripting API identity is
`CarbonLuau 0.4.0-experimental`; it is not stable or 1.0. The still-unreleased
candidate keeps 0.4.0 because GUI is additive to its first public compatibility
surface rather than a break from an already published 0.4 line.

## Addon composition

Addon manifests can declare required and optional dependencies, a `main` module,
and explicit `publicModules`. Consumers import through their exact dependency
bindings:

```lua
local Economy = require("@economy")
local Formatting = require("@economy/formatting")

if addon:IsDependencyAvailable("metrics") then
    local Metrics = require("@metrics")
end
```

Local `require("private/util")` behavior is unchanged. Public modules return the
defining addon's canonical same-VM value, so shared tables and closures are shared
by reference. Private modules remain private. Missing, undeclared, stale or
non-public imports raise controlled ordinary Luau errors.

## Server-driven GUI

```lua
local Gui = game:GetService("Gui")
local Players = game:GetService("Players")
local Screen = Gui:Create("ScreenGui")
local Button = Screen:Create("TextButton")

Button.Text = "Click"
Button.Activated:Connect(function(Player)
    Button.Text = Player.Name
end)

for _, Player in Players:GetPlayers() do
    Screen:Show(Player)
end
```

The public GUI boundary includes ScreenGui, Frame, TextLabel, TextButton,
ImageLabel, ImageButton, ScrollingFrame, UIListLayout, UIPadding, immutable
UDim/UDim2/Vector2/Color3/ImageSource values, retained parenting/properties,
Clone/Destroy, explicit per-Player Show/Hide and secure Activated callbacks.
LayoutOrder controls deterministic list geometry independently of ZIndex.
Scrolling configuration is retained, while current scroll position remains
client-local and unobservable. One retained tree may be shown to several
Players; use Clone for independent per-player state. CarbonLuau coalesces
bounded synchronization toward the newest committed state and exposes no raw
Rust CUI or client-command authority.

TextBox is not implemented. The inspected Rust InputField command transport
trims submitted text and cannot satisfy the exact D16 text-preservation
contract. CarbonLuau intentionally does not expose lossy console-argument
semantics. Text input may be reconsidered if a future host provides a bounded
opaque text-preserving transport.

Authenticated-client visual layout, image appearance/loading, clipping,
scrollbar behavior, independent Player scrolling and actual click receipt
remain unqualified and are not implied by this experimental API designation.
See the [GUI guide](../api/Gui.md).

## Lifecycle and containment

- Providers register copied immutable schema-1 snapshots through
  `CarbonLuau.Addons` protocol 1.2.
- Required dependency loss retires and blocks affected consumers; restoration
  reconstructs eligible consumers against the new exact lifetime.
- Optional consumers do not hot-bind or hot-rebind.
- Provider unload retires its registrations. CarbonLuau reload invalidates all
  provider tokens and requires explicit fresh registration.
- One saturated addon cannot monopolize the global scheduler, and future-only
  tasks do not create persistent per-frame work.
- The 64 MiB VM default remains one shared cap, not a per-addon or process limit.

## Qualification

Root-only, 1, 10, 50 and 100-addon configurations passed on Windows and Linux.
The matrix covered memory and latency measurements, scheduler saturation,
shared-heap exhaustion, parser boundaries, provider and CarbonLuau unload/reload,
stale tokens, required/optional dependency transitions, native DLL teardown,
ASan, UBSan and leak detection. GUI qualification additionally covered retained
semantics, publication, exact ownership, rendering plans, dirty synchronization,
token security, replacement/recovery/teardown and bounded stress. Foundation 2
release-candidate qualification covered rich screens at 1, 10, 50 and 100
viewers, reaching 254 projected elements under the 257-element limit without
unbounded dirty or retry growth. See the [Foundation E record](../FoundationE.md),
[GUI Foundation 1G](../GuiFoundation1G.md) and
[GUI Foundation 2F](../GuiFoundation2F.md).

The candidate source was subsequently reorganized into explicit managed and
native invariant owners without an intentional behavior or identity change. See
the [Foundation F architecture record](../FoundationF.md).

All source compilation is subsequently contained by the shipped pinned compiler
worker with a one-second wall deadline, bounded protocol and clean restart after
timeout or failure. Linux, sanitizer and packaging qualification passed. Windows
live/local Foundation G qualification remains deferred and unqualified, so the
Foundation G verdict is PARTIAL and this is not a fully Windows-qualified
compiler-worker claim. See the [Foundation G record](../FoundationG.md).

## Not included

There is no addon directory scanner, package downloader, remote registry,
lockfile, version solver or parallel package instance. Provider-defined C#
capabilities, root-to-addon imports, addons depending on the root, restricted
exposure profiles, async capabilities and per-addon hard heap isolation remain
deferred. Inventory/items, TextBox, Submitted, UIGridLayout, automatic sizing,
CanvasPosition, URL images, advanced styling and hover/focus events remain
outside the surface.
Authenticated real-client GUI observations remain explicitly unqualified.
