# CarbonLuau v0.7.0 experimental

This experimental release includes the complete current scripting API,
`0.7.0-experimental`, with native ABI `1.5`, provider protocol `1.2`, addon
schema `1` and the unchanged pinned Luau revision.

The [qualification record](../Support.md#evidence-scope) separates controlled
live hosts, real-VM/model tests and final-source publication gates. Archives,
checksums and provenance are published only after those gates pass.

## What is included

- Luau scripting, commands, private addon domains, providers and dependencies.
- Retained GUI layouts, images, scrolling, grids, clipping and fonts.
- Local durable DataStoreService with asynchronous Get/Set/Remove and bounded
  structured Query; values remain private to the root or addon namespace.
- Read-only Workspace/Entity lookup and bounded asynchronous radius discovery.
- PlayerDied/PlayerSpawned and EntitySpawned/EntityDied/EntityDestroyed Signals.
- PlayerInventory reads, InventoryOnly GiveItem, TakeItem and sampled ItemChanged.
- Declarative Loot Replace for the qualified barrel prefab and item allowlist.

## Breaking inventory migration

Player HasItem, CountItem, GiveItem and TakeItem are removed without aliases.
Acquire `Player:GetInventory()` and invoke those methods on PlayerInventory.
See the [migration guide](../api/Inventory-Migration.md).
API declarations retain their historical introduction versions; their inclusion
here does not change earlier releases.

## Experimental limits

World and gameplay adapters require the exact qualified Rust/Carbon host tuples
and an initial-startup observer. First hot installation or full plugin unload
breaks continuity and requires a server restart for World admission.
Discovery evaluates candidates when encountered; it is not an atomic world
snapshot. Trusted external host mutations may race observations but cannot
authorize stale-proxy retargeting or unsafe CarbonLuau reads.

ItemChanged reports sampled physical net changes, not individual completed
inventory operations; balanced changes between samples may be missed.
Death is not removal and there is no universal ordering across Entity Signals.
Entity killer attribution is restricted to proven original-connection synchronous
melee RPC provenance; unproven attribution is nil.

Loot supports only `loot-barrel-1.prefab`, `scrap`, `metal.fragments` and
`Enum.DropMode.Replace`. It replaces qualified destruction-time payouts, not
earlier generation-time world drops. Post-COMMIT partial or indeterminate payouts
have no vanilla fallback, replay or compensation.

Persistence uses the qualified local PERSIST/EXTRA durability envelope. Logical
quotas do not reserve physical capacity; file extents are hard bounded while
filesystem allocation has a qualified operational budget. Uncertain mutations
are never automatically replayed. No physical power-loss guarantee is claimed.

Authenticated-client GUI rendering/clicks, scroll/font/clipping behavior and
Teleport convergence remain unqualified. Shockbyte full-runtime and macOS server
support are not claimed. TextBox is not implemented; broader Loot modes, Entity
mutation, inventory operation events, arbitrary SQL, cloud persistence and generic
host hooks remain deferred. No editor VSIX is published with this runtime release.
