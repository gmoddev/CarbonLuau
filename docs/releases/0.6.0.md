# CarbonLuau v0.6.0: planned experimental release

These are release-readiness notes for the next package. v0.6.0 has not been
published or tagged. The latest published package remains v0.5.0. Final
qualification and publication handoff are recorded in
[World/Entity Foundation 2C](../WorldEntityFoundation2C.md).

This additive release introduces read-only Workspace/Entity lookup and bounded
asynchronous radius discovery under scripting API `0.6.0-experimental`.
Existing addon, GUI, Player/inventory and persistence/Query APIs retain their
contracts and introduction versions. This remains experimental.

## World observations

`game:GetService("Workspace")` supplies exact keyed `GetEntityById(Id)` and
`GetEntitiesInRadiusAsync(Position, Radius, Callback, Options?)`. IDs are
canonical decimal strings, not Luau numbers or persistent lifetime keys.
Entity exposes read-only Id, full Prefab and root world-space Position. Equality
compares exact host lifetimes. Old proxies never retarget an entity that later
uses the same network ID; stale host-backed reads fail with controlled errors.

Discovery submits without yielding and later calls back with the complete dense
Entity array and nil error, including an empty array, or nil array and a
controlled error. It requires committed execution; use `task.defer` at startup.
Radius is finite/nonnegative. Options supplies an exact full Prefab and integer
Limit 1..256, default 256. A 257th default-limit match fails the whole query.
Handle both submission rejection and later failure. Retirement discards old
callbacks, and callback error/timeout never replays work.

See [the discovery guide](../api/Discovery.md),
[Workspace](../api/Services/Workspace.md), [Entity](../api/Types/Entity.md),
[options](../api/Types/EntityDiscoveryOptions.md) and
[runnable examples](../api/World-Examples.md).

The query captures a completed-Spawn cohort and samples positions at each
encounter. Later births are excluded. It is not an atomic world snapshot;
trusted host writers can race scalar observations. Results preserve physical
encounter order, not distance order. Every original lifetime is revalidated at
callback admission, and subsequent property reads remain live.

## Installation and qualification limits

World/Entity support is pinned to Rust build `25653776`, protocol `2634.289.1`,
revision `166494`; Windows Carbon `2.0.262.0` (`8a81d70`), Linux Carbon
`2.0.261.0` (`c74c4ca`), Harmony `2.4.2.0`, and the qualified Unity/assembly/hook
identities. Future builds require requalification. Windows x64 and glibc Linux
x64 remain the server targets.

Install CarbonLuau in the initial plugin batch and restart the Rust process.
First installation after world startup or full plugin unload/reload requires
another server restart to restore observer history. An unavailable world is a
controlled failure, never an empty successful query. Ordinary root/addon
replacement and VM recovery preserve the continuous observer while retiring
their old callback/facade authority. Consult [compatibility](../Compatibility.md)
and [installation](../Installation.md).

Discovery is bounded to 262,144 catalog/raw slots per query, eight pending
requests globally/two per domain, 1,024 shared scan/delivery units and raw slots
per frame, at most two deliveries within that budget, and 120 seconds from
acceptance through callback admission. Host pauses do not reset the deadline or
provide a callback-time guarantee. Results/captures and teardown remain bounded.

Authenticated-client GUI visuals, clicks, fonts, scroll effects and Teleport
convergence remain unqualified under their existing experimental policy. This
release adds no authenticated-player or natural Entity-pooling qualification.
Shockbyte full runtime, other operating systems/architectures and unqualified
host builds remain outside the support envelope. The earlier official VS Code
extension is not a matching 0.6 artifact; no VSIX or world preview is bundled.

## Identities and deferred features

The planned package/tag are `0.6.0`/`v0.6.0`, assigned only by a separately
authorized publication task. Development API is `CarbonLuau 0.6.0-experimental`.
Native ABI `1.5`, provider protocol `CarbonLuau.Addons/1.2`, addon schema `1`,
Luau `c6b830185af962c82003f86784e2fe036357c830` and private SQLite `3.53.4`
remain unchanged. Package and scripting API identities are separate.

There are no Entity Signals, Spawn/Destroy, Position writes, raw host objects,
specialized entity capabilities, general enumeration/query DSL, movement/spatial
index, public cursor or cancellation handle. TextBox is not implemented for
the existing exact-text transport reason. Persistence keeps its existing
durability, quota and no-replay limits; it does not serialize Entity facades.
