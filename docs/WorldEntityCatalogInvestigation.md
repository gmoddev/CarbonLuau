### Exact outstanding theorem

The narrow guard is a viable **research candidate**, not a proven impossibility
and not a qualified primitive. Independent review agrees that owner-thread
serialization excludes new owner-thread scheduling/reparenting between guard and
getter in a no-yield/no-reentrancy segment. Foundation 1 already accepts the
ordinary getter's correct current-position behavior: the same getter's zero
branch reads TRS/parents without an additional lock. Do not demand an independent
proof against every hypothetical undisclosed engine writer to reuse that existing
correctness premise. The **new hard-work obligation** is excluding a dependency
publication between the guard and the getter, and keeping the guarded native
descriptor/storage/topology stable through the segment. A getter which then waits
could remain correct under F1 while violating Foundation 2's work bound.

The focused Linux follow-up identified the concrete mechanism, not merely missing
API documentation:

- `0xc044c0` passes the recorded dependency through `0xc05c30` -> `0xc07fd0`,
  which can wait/help execute work; only after return does it clear group/version.
  `0xc044b0` also clears them. Zero is an empty dependency record, not an
  independently qualified acquire handshake or worker-completion flag. A finished
  job may leave a nonzero record until explicitly drained.
- Transform-job hierarchy enrollment reaches publisher `0xd23800` through
  `0xd2ab50` / `0xd2abd0`; it stores version at `[H+8]`, then group at `[H+0]`.
- Another native path, `0xb940e0`, schedules/flushes work before calling that
  publisher at `0xb94884`. There is therefore an enrollment window, harmless
  **if serialized with the guarded owner-thread read**, but not yet excluded by
  an exact callback-affinity proof. The associated inspected worker `0xb98f60`
  updates change masks; it did not establish concurrent TRS/topology relocation.

The available ELF has no internal debug symbols and refers to an absent local
`UnityPlayer_s.debug`. Its inspected calls do not settle that callback's owner-
thread/serialization contract. The already-preserved synchronization/enrollment
findings in [the movement record](WorldEntityDiscoveryMovementInvestigation.md)
remain evidence, not a reopened motion inventory. No concrete supported concurrent
publisher counterexample is established either. Windows guard observations do
**not** prove Windows internal publisher equivalence/affinity.

Before adopting it, prove for the pinned native hierarchy:

> The identified hierarchy-dependency publishers cannot install new relevant work
> during the uninterrupted owner-thread guard/getter segment; its exact native
> descriptor and parent storage/topology remain valid and stable for that segment.

Also qualify fixed-cost current Handle acquisition/validity and marshaling, exact
same-Transform identity, safe parent indices/buffer lifetime, and the full getter
path on both platforms. Repeated zero checks or matching observations cannot
replace the synchronization theorem. A successful proof could bound work by
`FixedGuard + (D+1)*ParentProbe + Getter(D)`; genuine pending dependency must fail
the **whole query** controlledly, and excessive depth must fail the **whole query**,
not omit that Entity as success. No continuous movement state is justified here.

## What Foundation 1 already supplies—and what it does not

[D20](Invariants.md#d20--worldentity-foundation-1) and the qualified
[1A](WorldEntityFoundation1A-Validation.md), [1B](WorldEntityFoundation1B-Validation.md)
and [1C](WorldEntityFoundation1C.md) records remain authoritative. Reuse their
full virtual Spawn boundary, startup observer, weak exact-object identity,
completed epoch, sticky retirement and domain/VM/publication authority.

The current `EntityLifetimeModel` is **not an enumerable complete live catalog**:

- `BeginSpawn` immediately retires `State.Current`, clears it and advances epoch.
- `CompleteSpawn` marks the qualified attempt Completed/Failed, but allocates no
  `LifetimeRecord` or Entity token.
- `TryAdmit` creates a token lazily, after qualified startup, valid host evidence
  and real caller authority. `TokenRecords` contains only previously admitted
  objects, with weak incremental cleanup. Enumerating it would miss untouched
  pre-existing world entities.
- `Validate` discovers destruction, lost occupancy, changed ID/prefab and other
  mismatches on demand. `Retire(Binding)` retires that binding, not the host
  lifetime. Domain/provider/VM retirement must not delete live world membership.

Consequently, add catalog enrollment to the already-qualified **outer completed
Spawn epoch** seam, not the token table or a fabricated domain binding. A slot
can initially represent an observed completed epoch awaiting ordinary D20 host
admission; it is not authority to publish an Entity. Mint/reuse the canonical
record and real-domain binding only through the existing admission rules when
needed. Do not eagerly call `TryAdmit` with a synthetic always-current authority.

Foundation 1 does not promise a perfect immediate destruction callback. Catalog
entries may therefore be conservative weak candidates until bounded sweeping or
encounter validation detects retirement. **Stale slots are allowed; stale results
and missing live observed epochs are not.** Catalog count is not an authoritative
live-entity count. This distinction avoids adding a new universal Kill theorem.

## Smallest catalog: fixed slots, no tree or motion state

Use a bounded slot array with a bounded free-slot pool. Live entries never move
to compact holes. Each activation stores a weak exact object, completed SpawnEpoch,
observer generation and monotonic private BirthSequence. The object state can
carry its slot index/birth link; no unbounded historical map is necessary.
Duplicates for the same observed epoch are idempotent. New epochs receive a fresh
birth even if object, ID, prefab and physical slot are identical.

At query acceptance capture the exact host/catalog lifetime, the highest allocated
slot extent H and BirthSequence upper watermark U. Walk indices `[0,H)` once;
inspect at most B slots per opportunity. Empty/stale/post-watermark slots still
consume inspected work. No registry enumerator, world snapshot, seen-world set,
sort, tree successor lookup, spatial cells or movement notifications are required.
Slots allocated after acceptance cannot enter that query, even when a freed slot
behind or ahead of its cursor is reused.

### Continuation theorem

For any completed epoch represented before acceptance which remains eligible
through its encounter, its slot stays at the same index below H and its birth
stays at or below U. The monotonic index cursor reaches that slot exactly once.
Removal cannot shift another entry behind the cursor. Reuse carries birth > U
and is excluded. Thus every continuously present initial-cohort candidate is
examined once, without duplicate evaluation or retained tombstone history.

An epoch retired before encounter is omitted. An epoch completed after acceptance
is excluded—even if placed into an unvisited old hole. Current root Position and
optional exact Prefab are evaluated at encounter, not at start/end. The world
does not freeze; success is complete for this explicit initial completed-epoch
cohort under encounter-time eligibility, not every transient newcomer. No network-
group subset or arbitrary prefix is a successful result. Exceeding result/work
limits fails the whole query, never silently truncates it.

Matches retain independent canonical lifetime/weak identity, captured ID/prefab
and caller authority, **not a borrowed mutable slot weak-reference holder**. Slot
reuse must not retarget queued results. Revalidate exact lifetime across the read
and before completion admission. A retained result retiring before admission
fails the query rather than becoming the new occupant of its ID. Movement alone
does not re-run filtering at delivery; later property reads remain live under D20.

### Lifecycle integration required

1. Outer Spawn entry removes/fences any prior catalog epoch synchronously, using
   the existing per-object state. No Luau entry, world walk or bulk cleanup.
2. Only the existing full-call successful completion verdict may activate a new
   slot. PENDING, failed, skipped or poisoned Spawn never enrolls as completed.
3. Track startup completions while query admission is closed. Open discovery only
   after the existing qualified startup reconciliation and catalog continuity/
   capacity checks pass. This covers pre-existing restored world entities without
   enumerating the lazy token table or creating an unqualified hotload baseline.
4. Reuse D20 sticky host-lifetime retirement when known; free that slot. Bounded
   background sweeping handles collected/destroyed/definitively retired candidates.
   Temporary non-admissibility must not erase an observed completed epoch that
   could later become eligible without a new Spawn. In particular, do not drop an
   unadmitted epoch just because registry occupancy is temporarily absent.
   This requires a bounded pre-admission eligibility check: existing `TryAdmit`
   marks invalid evidence Failed even if no record exists. Do not call it as a
   speculative maintenance probe and then retry the failed epoch. Once actual
   D20 admission/validation establishes sticky retirement, that epoch stays stale.
5. Unobserved same-object/same-epoch registry churn does not invent a new incarnation.
   An observed lost occupancy of an admitted lifetime follows existing sticky
   retirement. Different object/same ID and same object/new epoch cannot revive
   the old record. Do not change Foundation 1's admission semantics to simplify
   catalog maintenance.
6. Domain/provider/VM replacement discards pending callback authority but preserves
   host catalog membership. Observer gap, plugin unload or server restart invalidates
   discovery; the existing startup/restart deployment rule is unchanged.

Overflow must mark discovery incomplete/unavailable immediately; no silently
dropped enrollment or successful partial catalog. Existing Foundation 1 point
lookup need not be disabled solely by a catalog-capacity failure. Never reclaim
a possibly live slot to make room. Sweep under a separate hard budget before
exhaustion; do not synchronously scan the world from Spawn. Recovery after an
actual enrollment loss requires separately proven complete reconciliation or a
fresh qualified host startup, not merely an empty slot becoming available.
Birth/slot-link counter overflow likewise fails closed; no wrap or retargeting.

## Deriving policy without inventing numeric guarantees

Let C be catalog capacity, H <= C captured slot extent, Q concurrent accepted
queries, B slots per query opportunity, G global inspected slots per turn, R result
cap, F result validations/marshaling units per turn and S maintenance slots per
turn. Add a separate bounded query-state-transition budget: empty/error queries
consume scheduling work even when zero slots are read. All completed-but-undelivered
requests count against Q and per-domain admission limits.

Catalog metadata is O(C); continuations/results are O(Q + QR). A slot needs a
weak identity reference and epoch/observer/birth counters; the free-index pool is
also C-bounded. Exact managed object/layout/weak-reference bytes must be measured
on the chosen runtime, not inferred from Python object sizes. Preallocate or grow
in bounded startup/maintenance chunks. Results must not share mutable slot identity.
No unbounded record history, pending enrollment list, or world snapshot is allowed.

Use the existing 262,144-entry **startup reconciliation limit as sizing evidence
only**, not proof of a continuous live/catalog bound. Failed/dead completed epochs
can occupy slots until sweeping, so a live-count estimate alone is insufficient.
A fixed high-water H can retain holes after churn; every hole consumes work, but
the query still inspects at most C slots. Avoid relocating live slots to improve
throughput. A bounded free-slot/high-water optimization may be qualified later.

For an independently established worst-case slot-cost bound K, choose G so `G*K` fits the traversal
share of the owner-thread work envelope; B <= G. Separately fund maintenance S,
callback result construction/validation F and query transitions. Sum these shares
under one global budget, not Q independent full budgets. Given B-sized opportunities
and `k = floor(G/B) >= 1`, persistent round-robin serves Q ready queries in at most
`ceil(Q/k)` turns per round. A stable query requires `ceil(H/B)` scan opportunities
plus bounded completion opportunities (at most R results) and explicit setup work.
These are work/opportunity bounds, **not wall-clock guarantees during host stalls**.

An absolute deadline D begins at acceptance, never resets, and forbids late success.
Expiry and resource release occur at the next owner-thread opportunities under
bounded cleanup; an original-authority timeout callback can be delivered later.
No automatic retry/rescan or callback replay. Domain/VM retirement cancels delivery,
not world entities. Persistent per-domain round-robin plus per-domain/global query
caps (per-domain cap smaller than the global cap for shared use) prevent one addon
taking every slot/opportunity; cursor position survives turns. Fair service applies
to accepted ready requests, not a promise that every capacity-rejected submission
will eventually be accepted. Observer bookkeeping must also have its own bounded
per-invocation cost and accounted burst/resource policy; G only budgets traversal.

Numeric C/B/G/Q/R/F/S/D remain **unselected**: K is not yet proven, so deriving
latency-backed defaults now would hide the read gate. Once K and layout bytes are
qualified, run dense/empty/churn and concurrent-domain probes to select the smallest
useful policy. Do not call these synthetic capacities production defaults.
